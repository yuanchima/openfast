.. _versioning:

版本管理
~~~~~~~~~~
OpenFAST 遵循 `语义化版本管理 <https://semver.org>`_。总之，这
意味着版本号为 MAJOR.MINOR.PATCH 时，各组成部分将
按如下方式递增：

- MAJOR 版本：引入不兼容的 API 更改时，
- MINOR 版本：以向后兼容的方式添加功能时，以及
- PATCH 版本：进行向后兼容的 bug 修复时。

例如，``OpenFAST-v1.0.0-123-gabcd1234-dirty`` 对 OpenFAST 的描述如下：

=================== =============
 版本组成部分        说明
=================== =============
 v1.0.0              MAJOR.MINOR.PATCH 编号体系；对应于 NREL（2025 年后称为 NLR）在 GitHub 上标记的提交
 123-g               最近一次标签之后额外的提交数（``-g`` 表示 ``git``）
 abcd1234            当前提交哈希值的前 8 个字符
 dirty               表示进行了本地修改但尚未提交；若无本地更改则省略
=================== =============
